# 研究工作台 Research Workbench

面向 Android、macOS 和 Windows 的本地科研工作台。它将研究材料保存为独立快照，支持阅读、记录、整理研究关系、准备离线实验任务、接收运行结果并生成 Markdown 写作草稿。应用不自动执行任务中的命令，也不会将材料上传到云端。

## 目前可用的流程

1. 在“概览”导入研究目录或 ZIP。应用复制原文件到自己的资料库，识别 Markdown、PDF 和 JSONL；原目录保持不变。手机通常使用 ZIP 导入更方便。
2. 在“文库与证据”查看论文、主张、候选和实验条目，打开 Markdown/PDF 并保存页码、原文引句和定位笔记。在“研究关系”的可点击图中追溯已解析引用。
3. 在“研究任务”编辑任务目标和 JSON 规格，保存修订，导出离线任务 ZIP。Android 等平台使用系统保存对话框选择文件位置。
4. 在另一台设备导入任务 ZIP，核对代码、数据和环境后，明确点击“开始执行记录”。在可信外部工具中运行任务；回到工作台更新状态、指标、日志和待复审结论，并导出结果 ZIP。可选择附加一个原始产物文件。工作台从不自动执行包内命令。
5. 在原设备导入结果 ZIP 或 JSON，核对任务 ID、修订与产物后人工接纳；同一任务修订的运行可并排比较。执行状态不等于科学结论已验证。
6. 导入 research-skill 项目（v6.5 目录结构）时自动识别：跳过源码包、数据集和权重；同一记录只显示最新修订；论文与 `related_work/` 下的 PDF 自动绑定；交付物里的 `[kind/id@rev]` 可点击。精读笔记可在“概览”导出为待审的 V2 claim 草稿，工作台不写入项目日志，由人或研究 agent 补全后追加并运行 `check-research.py`。详见 [research-skill 集成](docs/research-skill-integration.md)。
7. 在“论文写作”为提纲关联原始条目、带页码引句的精读笔记或已接纳的运行结果，导出保留来源的 Markdown 报告。

Markdown 阅读与独立定位笔记已实现；PDF 阅读组件已接入，但仍待 Android、macOS、Windows 原生设备验收。笔记不会写回 PDF。提纲导出是保留证据来源的 Markdown 草稿，不包含 Zotero 式文献管理、引用格式化或完整论文排版。

同一局域网内可点击顶部“局域网传输”，明确选择单个文件并启动临时共享。接收端输入地址与配对码，下载后再选择导入研究材料、任务或结果。共享至多 10 分钟，首次配对下载请求后关闭；它不是后台同步或远程命令入口。不同网络继续使用人工传递文件。任务 ZIP 只包含规格与结果模板，代码/数据本体需要另外传递和核验。单个文件限制 30 MiB，导入包限制 150 MiB、10,000 个文件；大数据应使用外部存储并在规格中记录可验证的版本与校验值。

## 本地开发

需要 Flutter SDK、Dart SDK 和相应平台的原生工具链。运行 `flutter pub get`，再运行 `flutter run -d android`、`flutter run -d macos` 或 `flutter run -d windows`。检查使用 `flutter analyze` 和 `flutter test`。Windows 需要在 Windows 开发机上构建；macOS 需要完整 Xcode。当前仓库不包含任何私有研究材料。

需要在命令行试验导入时，可运行 `dart run tool/demo_import.dart <研究目录或ZIP> <临时应用数据目录>`。这会将材料复制到指定临时目录并输出对象数量，不会执行研究代码。请不要把真实研究数据目录提交进 Git。
